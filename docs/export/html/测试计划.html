1. 测试目标

  1. 验证 Petstore 宠物管理接口（增删改查、状态流转、异常场景）行为与契约符合预期；
  2. 验证 SauceDemo 核心用户路径（登录、购物车、商品排序、下单全流程、表单校验）；
  3. 沉淀可配置、可重复执行、可观测、可接入 CI 的自动化回归资产。

2.2 不纳入范围（Out of Scope）

  • 性能 / 压力测试、安全测试、兼容性全矩阵（仅覆盖 Edge 与 Chrome 无头）；

3. 测试策略

维度 策略
分层设计 四层：用例层 → 页面 / 接口对象层 → 公共封装层 → 配置层；Web 采用 Page Object
用例设计 正向 + 反向分离；参数化 + JSON 数据驱动；覆盖等价类（status 三取值）与异常输入（404、表单缺失）
用例组织 marker 分层：api / web / smoke（核心主流程 5 条）/ negative（反向 14 条）
接口断言 三层：HTTP 状态码 + 业务字段 + jsonschema 响应结构约束
数据管理 fixture 前置创建、finally 幂等清理、ID 随机化 → 用例可重复执行、环境无残留
稳定性 显式等待为主、等待时长可配置；失败重试仅限基础设施类异常（浏览器 / 驱动 / 网络），断言失败不重试
可观测性 失败自动收集：运行日志尾部 + 页面截图 + DOM 源码 + 浏览器 Console 日志（Allure 附件）
配置管理 config.ini 集中配置 + 环境变量覆盖（TEST_WEB_HEADLESS 等），本地与 CI 复用同一套用例
执行方式 单进程或 pytest-xdist 并行；CI 由 GitHub Actions 编排（push / 每日定时 / 手动触发）

7. 风险与应对

风险 影响 应对措施 实际结果
公开环境网络波动（连接重置 / 超时） 用例误报 重试仅针对基础设施类异常 + 失败取证 已生效（曾出现整批 ERR_CONNECTION_*，重跑即恢复）
React 应用在 CI 下点击 / 输入竞态 本地绿、CI 挂 点击 / 输入后校验状态提交，未达成交替用 JS 方式重试 已收敛为 CI 全绿
浏览器渲染差异（表单错误提示不渲染） 负向断言误报 断言改为业务规则（校验拦截 = URL 未跳转）+ 文案可选校验 已解决
前端元素变更 用例失效 定位器集中在 PO；失败自动留 DOM 源码定位 机制就绪
CI 首次下载浏览器驱动慢 流水线耗时增加 Selenium Manager 自动匹配；必要时 Re-run 已接受（首次 3~5 分钟）
