# 测试计划

> 本文档为本项目（自动化测试框架 + 被测站点回归）的测试计划模板，
> 用于面试展示「测试流程管理」能力。示例内容基于当前项目真实情况，可按需修改。

---

## 1. 目标与范围

### 1.1 测试目标
1. 验证 Petstore 宠物管理接口（增删改查/状态流转）行为符合预期；
2. 验证 SauceDemo 登录、购物车、商品列表、下单全流程关键用户路径；
3. 沉淀可复用、可配置、可观测的自动化回归资产。

### 1.2 测试范围（In Scope）
| 模块 | 被测对象 | 用例数 |
|------|----------|--------|
| 接口自动化 | Petstore /pet（查询、创建、更新、删除、按状态查询、数据驱动） | 12 |
| Web 自动化 | SauceDemo（登录正反向、购物车、排序、多商品加购、下单 E2E、表单校验） | 11 |
| 合计 | | 23 |

### 1.3 不在范围（Out of Scope）
- 性能/负载测试、安全测试、兼容性矩阵（浏览器仅 Edge/Chrome）；
- 被测站点非本团队开发的业务系统，不做需求级功能验收（仅做练习站回归演示）。

## 2. 测试环境

| 项 | 说明 |
|----|------|
| 接口环境 | https://petstore.swagger.io/v2（公开练习环境） |
| Web 环境 | https://www.saucedemo.com/（公开练习站点） |
| 语言/框架 | Python 3.10+ / Pytest 9.x / Requests / Selenium 4.x / Allure |
| 浏览器 | Edge（本地）/ Chrome 无头（CI） |
| CI | GitHub Actions（push/定时/手动触发） |
| 配置 | config.ini + 环境变量覆盖（TEST_*） |

## 3. 测试策略

| 层面 | 策略 |
|------|------|
| 接口 | 状态码 + 业务字段 + jsonschema 结构校验三层断言；数据前置于 fixture 自动创建、结束自动清理（幂等） |
| Web | Page Object 封装；显式等待为主；正向/反向分离；冒烟覆盖核心主流程 |
| 稳定性 | 仅对基础设施类异常自动重试 1 次；断言失败不重试 |
| 可观测性 | 失败自动附加：日志尾部 + 页面截图 + DOM 源码（Allure） |
| 执行方式 | 支持按 marker 运行：`-m api` / `-m web` / `-m smoke` / `-m negative`；支持 xdist 并行 |

## 4. 进入 / 退出准则

- **进入**：代码已提交且通过静态语法检查；被测公开环境可用；依赖安装完成。
- **退出**：计划内用例 100% 执行；严重/致命缺陷（若有）已澄清或被接受；报告已产出。

## 5. 主要风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 公开练习环境不稳定/被限流 | 用例误报 | 重试策略（仅基础设施类）+ 失败自动取证；必要时切私有 mock |
| 前端元素变更 | 用例失效 | PO 定位器集中维护；失败截图/源码快速定位 |
| CI 首次下载浏览器驱动慢 | 流水线超时 | Selenium Manager 自动匹配；缓存可后续优化 |
