# 缺陷复现演示（被测系统真实缺陷取证）

> 目的：回答面试官「**你测出过被测系统的问题吗？**」。
> 以下 2 个缺陷来自 SauceDemo 官方提供的 `problem_user`（该账号被站点刻意注入缺陷，
> 用于练习缺陷发现），均通过 `scripts/defect_probe.py` **真实浏览器探测取证**，非编造。

---

## 复现环境与工具

- 被测站点：https://www.saucedemo.com/（公开练习站点）
- 探测脚本：`scripts/defect_probe.py`（运行：`python scripts/defect_probe.py`）
- 探测日期：2026-09-06；浏览器：Edge（无头）

## 缺陷 1：problem_user 商品图片全部错乱（P2 / 视觉展示）

| 项 | 内容 |
|----|------|
| 前置条件 | 使用 `problem_user` / `secret_sauce` 登录 |
| 复现步骤 | 1) 登录；2) 打开商品列表页 |
| 实际结果 | 6 件商品的 `<img>` 全部指向**同一张**占位图（sl-404），`distinct_image_count = 1` |
| 预期结果 | 每件商品应展示各自商品图（对照 standard_user：6 张不同图片，`distinct_image_count = 6`） |
| 影响 | 商品无法辨识，影响下单决策；属视觉展示缺陷 |
| 定位线索 | `image_sample` 均为 `.../sl-404-Cq1a9k9X.jpg`（404 占位图） |

## 缺陷 2：problem_user 商品排序功能失效（P2 / 功能缺陷）

| 项 | 内容 |
|----|------|
| 前置条件 | 使用 `problem_user` 登录商品列表页 |
| 复现步骤 | 1) 选择排序「Name (Z to A)」；2) 再选择「Price (low to high)」 |
| 实际结果 | ① 名称降序后首项仍为 "Sauce Labs Backpack"（`za_reordered = false`，列表未变化）；② 价格升序后价格序列为 `[29.99, 9.99, 15.99, 49.99, 7.99, ...]`，**非升序**（`lohi_sorted_asc = false`） |
| 预期结果 | 与 standard_user 一致：名称降序首项变为 "Test.allTheThings() T-Shirt (Red)"；价格升序为 `[7.99, 9.99, 15.99, 15.99, 29.99, ...]` |
| 影响 | 用户无法按价格/名称浏览商品，影响核心浏览路径 |

## 工程处理立场（面试可讲）

1. **缺陷发现 ≠ 自动化跑绿**：自动化用例保证了「被测功能符合预期行为」，
   而缺陷发现依赖「反向验证/异常账号对比」——本项目用探测脚本做横向账号对比（standard vs problem）；
2. **不要把已知缺陷硬塞进回归套件**：若把 problem_user 的排序失败写成断言，
   回归会永久红，失去信号价值。更合理的方式是：缺陷文档 + 复现脚本（缺陷回归时人工/半自动验证）；
3. **自动化用例账号选择是有依据的**：因此排序/下单等用例统一使用 `standard_user`，
   `problem_user` 仅用于缺陷演示场景（本项目登录用例覆盖其登录成功路径即可）。
