## ① 项目经历（推荐直接粘贴的版本）

### 全栈自动化测试框架（接口 + Web）｜个人项目
**技术栈**：Python · Pytest · Requests · Selenium · Allure · jsonschema · pytest-xdist · GitHub Actions

**项目简介**：独立搭建接口 + Web 双端自动化测试框架，覆盖 Petstore 接口与 SauceDemo Web
两大被测对象；集成 Allure 报告、失败自动取证与 GitHub Actions 流水线，共 47 条用例全部通过
（接口 20 + Web 27）。

- **框架设计**：采用"用例层 → 页面/接口对象层 → 公共封装层 → 配置层"四层架构与 Page Object
  模式；定位器集中管理、页面跳转封装；正向/反向用例分离，用 marker 划分 api / web / smoke / negative，
  可按需运行（冒烟 5 条 / 反向 14 条）。
- **接口自动化**：基于 Requests Session 复用 + 统一超时 + 请求/响应日志；
  断言采用「状态码 + 业务字段 + jsonschema 结构校验」三层，共 20 条：增删改查与 404 异常、
  findByStatus 三取值参数化、JSON 数据驱动，以及边界与契约专项（中文/表情符号名称往返、
  256 字符超长名称、同 ID 重复创建覆盖语义、PUT 不存在 ID 行为自洽、非法入参与缺失字段
  不 5xx、Content-Type 与响应耗时契约）；测试数据由 fixture 前置创建、`finally` 幂等清理、
  ID 随机生成，保证用例可重复运行、无脏数据。
- **Web 自动化**：Selenium + PO 共 27 条，覆盖登录正反向、**未登录访问受保护页面重定向**、
  退出登录、商品排序 4 种（名称/价格 × 升降）、商品详情与列表一致性、购物车 5 种状态
  （空态/继续购物/部分移除/移除最后一件/加购-移除链路）、下单全流程 E2E、**订单金额计算校验
  （小计+税费=总计）**、取消下单、结算表单必填 3 场景；显式等待为主，等待时长可配置。
- **稳定性攻坚**：处理了 React 应用在 CI 环境下的不稳定问题（点击丢事件、受控输入值丢失、
  水合竞态），方案为"点击/输入后校验状态提交，未达成自动以 JS 方式重试"，并把
  "本地全绿、CI 必挂"收敛为 **GitHub Actions（Chrome 无头）全绿**。
- **可观测性**：失败自动收集 运行日志尾部 + 页面截图 + DOM 源码 + 浏览器 Console 日志
  （Allure），多数问题可一轮定位；提供失败自动重试（仅基础设施类异常，断言失败不重试）。
- **CI/CD**：编写 GitHub Actions 流水线（push / 每日定时 / 手动触发），接口用例 Ubuntu 运行、
  Web 用例 Chrome 无头运行；测试通过后自动生成并发布 Allure 报告到 GitHub Pages。
- **配置工程**：config.ini 集中配置 + 环境变量覆盖（TEST_WEB_HEADLESS 等），本地与 CI 复用同一套用例；
  pytest-xdist 并行，47 条全量回归约 62s（无头单进程 191s）。
- **文档沉淀**：输出测试设计说明、测试计划、测试报告模板、缺陷记录与踩坑复盘，具备完整流程意识。

### 项目可讲亮点（面试前背熟）
1. 四层架构与 PO 带来的维护性收益；
2. 数据"前置创建 + 幂等清理 + 随机 ID"如何保证可重复运行；
3. 三层接口断言（状态码/字段/schema）如何发现"契约漂移"；
4. React 稳定性问题的完整定位过程（证据驱动：截图/DOM/Console → 根因 → 方案）；
5. 失败重试的"克制"设计：只重试环境类异常，避免掩盖真实缺陷；
6. CI 三 Job + Pages 在线报告：从脚本到工程化的闭环。
