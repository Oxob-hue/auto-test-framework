## 二、可直接粘贴的三个版本

### 版本 A｜完整版（推荐，适合作为主项目，约 8~10 行）

**全栈自动化测试框架（接口 + Web）｜个人项目**
技术栈：Python · Pytest · Requests · Selenium · Allure · jsonschema · pytest-xdist · GitHub Actions

独立完成接口 + Web 双端自动化测试框架，共 **47 条用例**（接口 20 + Web 27）在本地与
GitHub Actions（ubuntu + Chrome 无头）**全部通过**，Allure 报告自动发布上线。

- 采用"用例层 → 页面/接口对象层 → 公共封装层 → 配置层"四层架构与 Page Object；
  定位器集中管理、页面跳转封装；正反向用例分离，marker 分层（冒烟 5 条 / 反向 14 条）按需执行；
- 接口测试基于 Requests Session 复用 + 统一超时 + 请求/响应日志，断言采用
  「状态码 + 业务字段 + jsonschema 结构校验」三层，覆盖增删改查、404 异常、状态三取值参数化、
  JSON 数据驱动，以及边界与契约专项（中文/表情符号名称往返、256 字符超长名称、
  同 ID 重复创建覆盖语义、PUT 不存在 ID 行为自洽、非法入参与缺失字段不 5xx、响应头与耗时契约）；
  数据由 fixture 前置创建、`finally` 幂等清理、ID 随机化，保证可重复执行、环境无残留；
- Web 测试用 Selenium + PO 覆盖登录正反向、未登录访问受保护页面重定向、退出登录、
  4 种排序、商品详情一致性、购物车 5 种状态、下单全流程 E2E、订单金额计算校验（小计+税费=总计）、
  取消下单与结算表单必填 3 场景；
- 解决 React 应用在 CI 下的稳定性问题（点击事件丢失、受控输入值丢失、水合竞态）：
  点击/输入后校验状态提交，未达成交替使用 JS 方式重试，把"本地全绿、CI 必挂"收敛为 **CI 全绿**；
- 失败自动收集 运行日志 + 页面截图 + DOM 源码 + 浏览器 Console 日志（Allure），
  并将失败摘要写入 CI Job Summary，多数问题一轮定位；重试只针对基础设施类异常，
  断言失败不重试，避免掩盖真实缺陷；
- GitHub Actions 流水线（push / 每日定时 / 手动触发）：接口用例 Ubuntu 运行、Web 用例 Chrome
  无头运行（环境变量切换，本地与 CI 复用同一套用例），测试通过后自动生成并发布 Allure 报告到
  GitHub Pages；`pytest-xdist` 并行使 47 条全量回归约 **62s**（单进程无头约 195s）；
- 沉淀测试计划、测试用例表（47 条明细）、测试设计说明、缺陷记录表、测试报告等文档，
  并提供 Excel/PDF 导出脚本，形成"计划 → 用例 → 执行 → 缺陷 → 报告"完整闭环。

## 四、技能清单（诚实版，每条都能被追问）

- **Python**：熟练编写自动化脚本与框架；类/装饰器/上下文、logging、configparser、pathlib、类型注解；
- **Pytest**：fixture 作用域与复用、conftest、参数化与数据驱动、hook（失败自动取证）、marker 分层、
  pytest-xdist 并行、pytest-rerunfailures 定向重试；
- **接口测试**：Requests（Session 复用/超时/日志封装）、jsonschema 结构校验、幂等与覆盖语义验证、
  边界与异常入参设计、测试数据隔离与清理；
- **Web 自动化**：Selenium 4、Page Object、显式/隐式等待、跨浏览器（Edge / Chrome 无头）、
  React 场景稳定性处理（重渲染与水合竞态）、失败取证（截图/DOM/浏览器 Console）；
- **报告与文档自动化**：Allure 报告、Markdown → Excel/CSV、HTML → PDF（Selenium CDP）导出脚本；
- **CI/CD**：Git 工作流、GitHub Actions（多 Job 编排 / 定时触发 / 产物与 GitHub Pages 发布）、
  Job Summary 与 Checks 观测、流水线失败定位；
- **质量意识**：正/反向与边界用例设计、冒烟分层、可重复执行、可观测性、测试文档化。

## 五、面试讲解要点（配合话术稿使用）

1. 四层架构 + PO 的维护性收益（改元素不改用例）；
2. 数据"前置创建 + 幂等清理 + 随机 ID"如何保证可重复执行；
3. 三层接口断言如何发现"契约漂移"，以及幂等/覆盖语义的验证思路；
4. React 稳定性问题完整定位过程（截图/DOM/Console 证据 → 根因 → 状态校验 + JS 重试）；
5. **CI 驱动改进**：CI 共暴露并修复 3 个问题（详情页返回 URL 误匹配、菜单展开误判元素存在、
   菜单动画导致的退出登录偶发）——体现"用流水线守住质量、按证据迭代"；
6. 失败重试的克制设计（只重试环境类异常，断言失败不重试）；
7. 文档闭环：计划 → 用例表 → 执行报告 → 缺陷记录，Excel/PDF 可直接交付。
